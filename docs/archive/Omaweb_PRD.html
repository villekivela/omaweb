Product Requirements Document

Omaweb: Modular Cross-Platform Web Browser

1. Executive Summary

Omaweb is a next-generation, cross-platform web browser engineered with a highly modular architecture. The core objective is to deliver a fast, keyboard-centric browsing experience featuring Vim-inspired workflows and an integrated side terminal, heavily optimized for Linux environments while supporting native development on macOS.

To ensure future-proofing and development stability, the browser will decouple its UI layer from the underlying rendering engine. It will utilize a QML-based frontend that seamlessly swaps between a bleeding-edge Ladybird backend and a stable QtWebEngine fallback at runtime.

2. System Architecture

The application is divided into three distinct layers: the UI Presentation Layer, the Abstraction/Adapter Layer, and the Engine Backend.

2.1 UI Presentation Layer (Qt/QML)

The entire user interface will be built using declarative QML. This provides hardware-accelerated rendering and simplifies the implementation of complex, dynamic layouts such as the integrated side terminal and fluid tab management.

2.2 The Engine Abstraction Layer

To support multiple rendering backends without code duplication, the QML layer will utilize a generic BrowserTab component. This component will implement a QML Loader that dynamically instantiates the correct engine backend based on a configuration flag.

2.3 Engine Backends

Backend Integration Method Primary Use Case
QtWebEngine Native QML WebEngineView Initial UI development, fallback stability, and reliable testing.
Ladybird CMake FetchContent + LibWebView Target experimental engine, isolated as a build-time dependency.

3. Theming & Customization Engine

A core requirement of Omaweb is advanced, runtime UI adaptability. The browser must not rely on static CSS or hardcoded themes; instead, it must react instantaneously to system-level theming tools.

Runtime Theming & Omarchy Integration

The UI must expose an IPC/D-Bus interface that listens for external style injections. When a system tool (e.g., Omarchy, Pywal, or custom theme managers) dispatches a new color palette, the C++ backend will intercept the payload and emit a QML signal. All QML color properties will be bound to a global ThemeContext object, allowing the entire browser interface to repaint with the new palette instantly without requiring an application restart.

4. Core Functional Requirements

  • Dual-Engine Support: The user or developer must be able to switch between the Ladybird and QtWebEngine backends without changing the core application code.
  • Ladybird Blackbox Integration: Ladybird must not be hard-forked. It will be pulled via CMake FetchContent. The integration layer will bridge WebView::ViewImplementation to a QQuickPaintedItem for QML rendering.
  • Vim-Inspired Navigation: Deep integration of Vim-style keybindings for scrolling, tab switching, and link hinting, handled at the QML level before reaching the engine layer.
  • Integrated Side Terminal: A native terminal emulator panel built alongside the web view, catering to developer-centric workflows.
  • Cross-Platform Build System: The CMake configuration must gracefully handle macOS AppKit dependencies during development while optimizing for Wayland/X11 on the Linux deployment target.

5. Implementation Phases

Phase 1: Foundation & Fallback

Establish the CMake project structure and build the foundational QML interface. Implement the BrowserTab abstraction layer and connect it exclusively to QtWebEngine. Develop the IPC listener for dynamic theming (Omarchy compatibility).

Phase 2: Ladybird Bridge

Integrate Ladybird via FetchContent. Develop the C++ LadybirdQmlItem wrapper that implements LibWebView interfaces. Wire the Ladybird shared memory bitmap into the QML painted item and route basic input events (mouse, keyboard).

Phase 3: Workflow & Polish

Implement the Vim-inspired keyboard handling and the integrated side terminal. Refine the dynamic theming system to ensure all UI elements (tabs, URL bar, terminal) correctly inherit injected color palettes at runtime.
