A keyboard-driven web browser for Omarchy.

It follows your desktop theme, keeps your data on your machine, and keeps work and personal apart in one window.

Install Features

01 / your theme, your browser

Built into your theme.

Omaweb reads its colours from whichever Omarchy theme you are running. Pick one to see the whole browser in it.

Preview theme

Work and personal stay in the same window.

Spaces are separate browsing identities inside one window. Each has its own cookies, logins, history, permissions and sessions, so you stay signed into work and personal accounts at once, with no second browser and no private window.

Pinned tabs sit across the top of the sidebar, the day’s tabs run under them, and a new tab opens on the Start page.

Your bindings.

Every browser binding lives in keybindings.json. Rebind a command there, or hand a key back to the page when a site wants it. Settings open beside your tabs, in the same window.

Built-in content blocking.

Filter lists come with the browser, and your own rules use uBlock Origin’s filter syntax.

Your files.

No browser account. No telemetry. No crash reports sent anywhere. Each Space keeps its own history, and clears it alone.

Optional Sync copies Spaces, tabs, keybindings and a few settings between your own machines through a private repository you own, and says exactly what it copies.

Hide the sidebar and the page takes the whole window.

Pinned tabs come back when a Space resumes. Mark one as Keep active and it keeps running in the background. Settings lists every tab kept this way, with the memory each one is using.

02 / getting it

Built for Arch.

Omaweb uses the Qt WebEngine your system ships, from Arch on x86_64 and from Arch Linux ARM on aarch64. Engine fixes arrive with your normal system updates, not with a new Omaweb release.

From the Omaweb repository

Add these lines to /etc/pacman.conf. Omaweb then arrives, and stays current, with the rest of your system updates. 

[omaweb]
SigLevel = Required DatabaseRequired
Server = https://villekivela.github.io/omaweb/$arch

Then import the key the packages are signed with, once. Check the fingerprint against this page: pacman installs nothing this key did not sign, and a keyserver will hand out any key that claims the name.

Packages are published for x86_64 and aarch64, and pacman asks for the one your machine runs. If you would rather not add a repository at all, the README has the other ways in. 

$sudo pacman-key --recv-keys FDA535B2185755EA718BEA585DBF15FE484EFA64
$sudo pacman-key --lsign-key FDA535B2185755EA718BEA585DBF15FE484EFA64
$sudo pacman -Syu omaweb

Keeping it current

Omaweb tells you when a new version is out. A mark appears at the bottom of the sidebar with the version and how to get it, and selecting it opens the release notes. Omaweb never installs anything on its own. With the repository added, the upgrade is your ordinary system update; without it, download the new package and install it the way you installed the first one. You can turn the check off in Settings, under About. 

$sudo pacman -Syu
