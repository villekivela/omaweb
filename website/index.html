Theme

Keyboard-driven browser · built for Omarchy

The browser should be part of your desktop, not a guest on it.

Every command is a keystroke you chose. Every login sits in a Space that cannot see the others. And the whole browser changes colour when you run omarchy theme set, because it reads the theme your bar and your terminal read, rather than a copy of it you keep in sync by hand.

Nothing needs the mouse

Every command is bound, and every binding is a line in one JSON file you own.

One overlay for everything

Addresses, search, tabs, Spaces and every browser command live behind Ctrl K. Links get letter hints with f. Scrolling is j and k, because of course it is.

Your bindings, not ours

Rebind anything, hand a conflicting key back to the page, and read the live sheet whenever you forget one. The Start page above is that sheet.

Themed with the rest of the desktop

Run omarchy theme set and the browser changes along with your bar, terminal and editor. Omaweb watches the theme Omarchy generates. No hook to install, no second colour scheme to maintain.

Two accounts, one window

A Space is an isolated profile, not a different person. Personal and work, side by side.

The same site, signed in twice

A Space keeps its own cookies, logins, history, permissions and session. Open your own account in one and your work account in another and the site never sees them as the same visitor. No second browser, no Private window, no signing out to switch.

Pinned tabs that stay put

Pin the handful of pages a Space is actually about and they come back every time it resumes. Mark one Keep active and it keeps running while you are elsewhere, and Omaweb always tells you which tab that is and what memory it is holding.

Where it stands

Omaweb is pre-alpha and says so. Do not put anything sensitive through it yet.

Working now

Spaces, Pinned tabs, the Omnibar, Keyboard navigation, docked Developer tools, Content blocking, session restore, tab management, Space-local History, Site permissions, certificate and cookie policy, and downloads that ask before writing a program down. Every page runs in its own sandboxed renderer, and the browser refuses to start without one.

Not finished

On Linux the window chrome, printing and notifications are still waiting on the Wayland port, and there is no package to install yet. The Ladybird adapter is still to be written. Omaweb also ships without URL reputation, which is a decision rather than a gap: Content blocking refuses some known malicious addresses, and that is not the same protection.

Next

The finished browser contract running under native Wayland on Omarchy and Hyprland, in an Arch package you install the ordinary way. Linux is the only platform Omaweb is distributed for; macOS is where it is developed. A browser that belongs in a tiling window manager rather than one that survives it.
