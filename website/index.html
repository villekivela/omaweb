The browser should be
part of your desktop,
not a guest on it.

A keyboard-driven browser built for Omarchy. It follows your theme and keeps your data on your machine.

Install Read the source Build from source Alpha Expect bugs, and desktop integration that is not finished. The README says what works today.

01 / your theme

Built into your theme.

Omaweb reads its colours from whichever Omarchy theme you are running. Pick one to see the whole browser in it.

Preview theme

02 / your keys, your data

Your browser. Your bindings. Your files.

omarchy theme set picks the theme. Everything else is a file on your machine.

Keys you own

Every browser binding lives in keybindings.json. Rebind a command there, or hand a key back to the page when a site wants it.

Local by default

No browser account. No telemetry. No crash reports sent anywhere. Your browsing data stays on your machine. Optional Sync copies Spaces, tabs, keybindings and a few settings between your own machines through a private repository you own, and says exactly what it copies.

03 / your spaces

Work and personal stay in the same window.

Spaces are separate browsing identities inside one window.

Keep accounts apart

Each Space has its own cookies, logins, history, permissions and sessions. Stay signed into work and personal accounts at once, with no second browser and no private window.

Pick up where you left off

Pinned tabs come back when a Space resumes. Mark one as Keep active and it keeps running in the background. Settings lists every tab kept this way, with the memory each one is using.

04 / getting it

Built for Arch.

Omaweb builds its own Qt WebEngine, for Arch on x86_64 and Arch Linux ARM on aarch64. It installs beside the one your system ships rather than over it, so nothing else on your machine changes, and engine security updates arrive from Omaweb with the rest of the browser.

From the Omaweb repository

Add these lines to /etc/pacman.conf. Omaweb then arrives, and stays current, with the rest of your system updates. 

[omaweb]
SigLevel = Required DatabaseRequired
Server = https://github.com/villekivela/omaweb/releases/download/repo-$arch

Then import the key the packages are signed with, once. Check the fingerprint against this page: pacman installs nothing this key did not sign, and a keyserver will hand out any key that claims the name.

Packages are published for x86_64 and aarch64, and pacman asks for the one your machine runs. If you would rather not add a repository at all, the README has the other ways in. 

$sudo pacman-key --recv-keys FDA535B2185755EA718BEA585DBF15FE484EFA64
$sudo pacman-key --lsign-key FDA535B2185755EA718BEA585DBF15FE484EFA64
$sudo pacman -Syu omaweb

Keeping it current

Omaweb tells you when a new version is out. A mark appears at the bottom of the sidebar with the version and how to get it, and selecting it opens the release notes. Omaweb never installs anything on its own. With the repository added, the upgrade is your ordinary system update; without it, download the new package and install it the way you installed the first one. You can turn the check off in Settings, under About. 

$sudo pacman -Syu
