Pre-alpha Linux browser for Omarchy

The browser should be
part of your desktop,
not a guest on it.

It is a desktop-native, keyboard-driven browser for Omarchy users who want browsing to fit into the system they already chose.

Read the source Build from source

01 / the window itself

Generated, not staged.

One set per theme, rendered from the source tree with no compositor and no screen grab, each over a wallpaper generated from that theme’s own palette. A chrome change is a re-run rather than a photo session.

Preview theme

02 / part of the desktop

One window among the rest.

Omaweb takes its cues from the desktop instead of bringing another one.

Theme, not a skin

Omaweb reads the theme generated by omarchy theme set, alongside your bar, terminal and editor.

Keys you own

Browser bindings and page-key rules live in keybindings.json. Rebind a command, or give a conflicting key back to the page.

Local by default

No browser account, telemetry or automatic crash upload. Omaweb keeps its browsing data on your machine.

03 / browsing identities

Work and personal stay in the same window.

A Space keeps the browser data one part of your life leaves behind.

Keep accounts apart

Each Space has its own cookies, logins, history, permissions and session. Work and personal accounts can stay open without another browser or a private window.

Carry the right context forward

Pinned tabs return when a Space resumes. Mark one as Keep active to leave it running, then see which tab is active and how much memory it uses.

04 / Status

The Qt browser contract is complete. Release qualification is not.

Omaweb is pre-alpha while Arch packaging and final Wayland release work continue.

Available now

Spaces, Pinned tabs, the Omnibar, Keyboard navigation, docked Developer tools, Content blocking, session restore, tab management, Space-local History, Site permissions, certificate and cookie policy, and downloads that ask before writing a program down. Every page runs in its own sandboxed renderer, and the browser refuses to start without one.

Release work

Native Wayland qualification, an Arch package and release automation are the remaining path to a daily-driver release.

Built in the target environment

Omaweb is developed on Omarchy. It already runs as a native Wayland client; packaging and final release checks remain.
