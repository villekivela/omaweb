What is synced,
and what is not.

Sync is optional and does nothing until you connect it. It copies a fixed list of browser state between your machines through a private Git repository you own. There is no Omaweb account, no Omaweb server, and no Private window is ever included.

01 / identity

Your GitHub login is the identity.

Omaweb does not create or operate a browser account.

No account to sign up for

Signing in to GitHub is what pairs your machines. Omaweb runs no account service and keeps no account database. Nothing about you reaches the Omaweb project.

A repository Omaweb maintains

Omaweb creates a private omaweb-sync repository and reuses one it can identify as its own. An unrelated repository with that name is never adopted; Omaweb takes a numbered name instead. Commits carry your GitHub login as the author.

02 / what is copied

Encrypted, readable, or never sent.

Every piece of browser state is in exactly one of these three lists.

Encrypted before upload

Space names and colours, ordinary tabs, and Pinned tabs. Each is a separate record, encrypted on your machine with XChaCha20-Poly1305 under your recovery key. GitHub stores ciphertext and cannot read these.

Readable in the repository

Your complete keybindings.json, your filter subscription addresses, and four Settings keys: floating-controls, ease-sidebar, use-favicons and tint-favicons. These are stored as plain text. Anyone who can read the repository, GitHub included, can read them.

Never synced

Passwords, cookies and active logins. Browsing history. Downloads. Site permissions. Per-site content-blocking exceptions and user rules. Everything in a Private window. Which Space and tab you currently have open stays on the machine, and so does your theme.

03 / what GitHub can see

What encryption covers, and what it does not.

Records are encrypted and authenticated. The repository around them is not.

Covered

The contents of every Space and tab record, and any alteration to them. Each record authenticates its schema version, kind and identifier, so a changed record is rejected rather than applied.

Not covered

That the repository exists, how large it is, and when it updates. The readable configuration above. Your login on each commit. That you use Sync at all.

04 / permissions

What the GitHub App asks for.

Two repository permissions, and what they reach once installed.

The two permissions

Repository administration: write, so Omaweb can create the private Sync repository. Repository contents: read and write, so Omaweb can identify that repository and reconcile the files in it.

The scope you actually grant

GitHub grants both permissions across every repository you select while installing the App. Omaweb asks you to choose Only select repositories and pick only omaweb-sync, which keeps the grant to that one repository. Inside a selected repository, administration write is GitHub's full repository-administration permission, which is broader than creating it.

Why you confirm the repository yourself

GitHub does not let an uninstalled App create a personal repository, and its installation form does not accept zero selected repositories. So Omaweb opens GitHub's new-repository form with the name, owner, description and Private visibility already filled in, you confirm it, and the App is then installed for that repository.

05 / the recovery key

The recovery key.

The key that decrypts your Space and tab records never reaches GitHub or Omaweb.

Shown once

The first machine generates a random 256-bit key and keeps it in Linux Secret Service. Omaweb shows it once, grouped and checksummed, to copy or save as a file only you can read. Carry it to your second machine yourself.

Lost means lost

Omaweb cannot recover the key and neither can GitHub. If every copy is gone, the encrypted Space and tab records cannot be read again. A wrong or missing key applies nothing and pauses Sync, so a typo changes neither machine. Changing the key in place is not offered; it needs a new repository and an explicit migration.

06 / timing

Local first, reconciliation after.

Your browser never waits for Sync. A change is saved on the machine first, and reconciled afterwards.

When it contacts GitHub

Thirty seconds after your last change, every five minutes while Sync is on, after reconnecting, and when you press Sync now. An expired access token is refreshed first. Your avatar is fetched once, when you log in.

Pause and disconnect

Pause stops the requests and keeps your credentials, local checkout and repository. Disconnect deletes the local Sync credentials, checkout and avatar. The GitHub repository stays where it is; delete it on GitHub if you want it gone.

07 / history

Repository growth and history.

How Omaweb bounds growth, and what that does not mean.

Compaction

After 256 commits or 30 days, Omaweb replaces the history with a fresh snapshot and advances a repository epoch. Deleting a tab or Space writes an encrypted tombstone, kept for 90 days, so a machine that was offline does not bring back something you closed.

Not secure erasure

Compaction bounds ordinary growth. It does not erase what a forge already holds: GitHub can retain backups and unreachable objects after the history is replaced.

08 / setup

Setting it up.

Sync is Linux-only and is unavailable in a Private window.

The first machine

Open Settings and choose Connect. Authorize on GitHub with the code shown. Confirm the prefilled private repository. Install the App for only that repository. Save the recovery key when it appears.

Every machine after

Sign in to the same GitHub identity and enter the saved recovery key. The Sync adapter notes cover the key and the setup flow in more detail.

09 / providers

GitHub is the first provider.

Forge authorization, repository provisioning and git reconciliation are separate interfaces, so a Forgejo or Gitea adapter can take GitHub's place without Omaweb growing an account system. This release offers no arbitrary server field: another forge needs its own App registration and trust messaging. The decision record has the reasoning, and the network request ledger lists every automatic request the browser makes.
